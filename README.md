# BizPortal: демо-версия коммерческого проекта

Это фронтенд веб-портала для компаний. Пользователь подаёт заявки на услуги платформы, проходит проверку и получает баллы и статус. В личном кабинете он ведёт данные компании, сотрудников и транспорт, а также свои заявки с фото и геолокацией.

Проект сделан для реального заказчика под NDA. В этой копии код и архитектура оригинальные, но всё, что указывает на заказчика, заменено нейтральными заглушками (список ниже). Эти заглушки поставлены сознательно, а не прикрывают недоделанную функциональность.

## Стек

- **Vue 3** (`<script setup>`, Composition API) + **TypeScript**
- **Vite 7**, **Tailwind CSS 4** (дизайн-токены через `@theme`), SCSS для градиентов
- **vue-router 4**: публичные и приватные маршруты, guard, выбор layout через `meta`
- **vue-i18n 11**: локали `uz` / `ru`
- **axios** с интерсепторами: refresh-токен с очередью запросов, автоматические тосты, распаковка ответа
- **Pinia** (только для auth), **@vueuse/core**, **swiper**, **vue-select**, **maska**
- **@neodx/svg**: сборка SVG-спрайта с типизированными именами иконок
- **Vitest** + **@vue/test-utils** + **happy-dom**: 25 тестовых файлов, 168 тестов, все проходят

## Архитектура

Проект построен по **Feature-Sliced Design**. Слой может импортировать только из слоёв ниже:

```
app → pages → widgets → features → entities → shared
```

| Слой | Что лежит |
|---|---|
| `app` | провайдеры (axios, i18n, pinia, toast), роутер, стили, auth-store |
| `pages` | тонкие компоненты маршрутов |
| `widgets` | составные блоки: шапка, навбар, блоки главной, разделы кабинета |
| `features` | бизнес-срезы (`auth`, `cabinet/company`, `cabinet/employees`, `cabinet/profile`, `cabinet/services`, `news`, `services`) |
| `entities` | доменные сущности: `submission`, `criterion`, `region` |
| `shared` | UI-кит, утилиты, типы, конфиг, ассеты |

Внутри фичи код разделён на `api/` (HTTP-запросы и типы), `model/` (composable `useX` с состоянием, загрузкой и валидацией) и `ui/` (только рендер). Наружу каждый срез отдаёт свой `index.ts`, а компоненты подключаются лениво через `defineAsyncComponent`.

Некоторые решения, на которые стоит обратить внимание:

- `src/app/providers/axios/interceptors`: обновление токена при 401 с очередью параллельных запросов и типизированный `HttpClient`, который возвращает `ApiResponse<T>`.
- `src/shared/ui`: собственный UI-кит (модалки, таблицы, табы, селекты, инпуты, пагинация и т.д.) с тестами рядом с компонентами.
- `src/shared/utils/routerPermissions.ts`: guard для публичных и приватных маршрутов.

Подробные правила проекта для разработки описаны в [CLAUDE.md](CLAUDE.md).

## Что заменено заглушками и почему

Всё перечисленное ниже заменено из-за NDA с заказчиком. Логика вокруг этих мест не менялась.

| Что | Что было в оригинале | Что теперь |
|---|---|---|
| Адрес API | `.env` с адресом боевого сервера | `.env.example` с `https://api.example.com/api/v1` |
| Контракт API | OpenAPI-схема бэкенда заказчика | не включена. Типы в `api/` написаны по ней и сохранены как есть |
| Название и бренд | название платформы заказчика | **BizPortal** |
| Логотип, фавикон | логотип заказчика | нейтральный значок-шестиугольник |
| Фирменные цвета | палитра заказчика | фиолетовая палитра. Классы и варианты переименованы в `primary` |
| Изображения | макеты приложения, иллюстрации и фото с брендингом | нейтральные SVG-иллюстрации в `src/shared/assets/images` |
| Тексты (`locales/*.json`) | описание платформы, льгот и FAQ заказчика | нейтральные тексты того же объёма и структуры |
| Вход через госсервис | кнопка входа через гос. SSO | обезличена до «Войти через SSO» |
| Статистика на главной | реальные цифры платформы | демо-числа в `widgets/home/header/model/useHeaderStats.ts` |
| Центр карты по умолчанию | координаты города заказчика | нейтральные координаты |

Без настоящего бэкенда интерфейс собирается и открывается, а запросы к API ожидаемо падают. Главную и страницу 404 можно посмотреть без бэкенда, для личного кабинета нужна авторизация.

## Запуск

Нужны Node ≥ 22.12 и Yarn 1.

```bash
yarn install
cp .env.example .env.development   # при необходимости указать свой API
yarn dev        # dev-сервер
yarn test       # тесты (yarn test --run для однократного прогона)
yarn build      # production-сборка
```
